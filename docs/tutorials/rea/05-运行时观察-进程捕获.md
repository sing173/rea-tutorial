## 第 5 章 运行时观察：进程捕获

> 状态：初稿，已按章节拆分。本轮重点校对第 1–2 章；本章后续按 raw/wiki 逐条补证。

### 1 它能做什么

Process Capture 运行一个调用方指定的命令场景，记录有界的终端行为、交互、生命周期和选定文件系统状态，用于比较两次直接运行。

### 2 场景 JSON

```json
{
  "executable": "node",
  "arguments": ["-e", "console.log('ready')"],
  "timeout_ms": 5000
}
```

执行：

```bash
rea capture-process ./scenario.json --json > capture.json
```

比较：

```bash
rea compare-process-captures capture-a.json capture-b.json --json
```

**名称解析**

| 名称 | 含义 |
|---|---|
| process capture | 运行一个有界命令场景并记录终端/生命周期/文件系统观察。 |
| scenario | 描述可执行文件、参数、超时、交互和观察路径的 JSON。 |
| PTY | 见第 1 章；伪终端。 |
| filesystem observation | 只对选定路径做快照，不限制进程读写。 |

### 3 关键边界

- **不是沙箱**：以当前用户权限运行，继承宿主环境。
- 文件系统观察路径只决定快照什么，不限制进程读写。
- 继承环境不记录；其影响可能 unknown。
- 新捕获需要 Linux/macOS + 原生 PTY；Windows 只能比较已有 Evidence。
- 进程族取消/清理失败要保留状态；PID + 路径不能证明退出后的所有权。

### 4 长驻服务怎么办

`capture-process` 适合一次性的 CLI、测试脚本或短命令。WeKnora Lite 这种长驻桌面应用不要用它捕获整个进程；应使用：

- API/Swagger 的请求/响应
- app 日志
- Postgres/Redis 状态
- 必要时用浏览器场景观察 UI
