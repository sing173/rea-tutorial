## 第 11 章 常见坑与检查表

> 状态：初稿，已按章节拆分。本轮重点校对第 1–2 章；本章后续按 raw/wiki 逐条补证。

### 1 常见坑

| 坑 | 处理 |
|---|---|
| 256 MiB 上限 | 改用 `go version -m` 读取完整文件，或直接用 Ghidra 分析 |
| `inspect-go-binary` 当反编译 | 它只读构建信息，不恢复函数逻辑 |
| 静态结果当运行事实 | 静态 ≠ 运行时 |
| Provider 未安装 | `rea doctor`；先做静态盘点 |
| Go stripped | 源码优先，二进制验证 |
| MCP HTTP 无认证 | 只绑本机/内网 |
| AgentEnv bundle 泄漏 | 分享前审查响应体、路径、token |
| 退出 0 当完整 | 检查 coverage/limitations/unknowns |
| 未授权目标 | 先确认授权/许可/范围 |

### 2 调查前检查表

- [ ] 目标身份（版本、SHA-256、路径）已记录
- [ ] 授权范围与停止条件已确认
- [ ] 使用隔离环境/测试数据
- [ ] 知道目标格式与可用 provider
- [ ] 已保存 Evidence 输出路径
- [ ] 知道哪些结论还缺覆盖

### 3 报告检查表

- [ ] observed / inferred / unknown 分开
- [ ] 写明 provider、版本、操作、输入
- [ ] 写明 limitations/coverage
- [ ] 不把静态检查写成运行结论
- [ ] 不泄露凭据/用户数据
