## 第 2 章 安装、注册与就绪检查

> 本章依据：R3 `docs/installation.md`、R4 `docs/ida-provider.md`、R5 `docs/ghidra-provider.md`、R9 `docs/process-capture.md`、R10 `docs/binary-diagnostics.md`、R11 `docs/reverse-engineering-tools.md`、R13 `docs/testing.md`，以及 W2/W6 和 E1 本机实测。文末列精确路径/行号。

> 本章的专用名称大多已在第 0/1 章“名称解析”中定义；这里只补充安装相关的新名称，不重复解释。

### 1 运行时要求

- Node.js `22.x >= 22.23.4`
- Node.js `24.x >= 24.22.1`
- Node.js `>= 26.12.1`
- 不支持 Node `23.x`、`25.x`

REA 不会自动升级 Node、npm、Homebrew、Java、Ghidra 等；provider 工具由你自行准备。

> 依据：R3 `docs/installation.md:1526`；R1 `README.md:180`；W6 `entity-rea-installation.md`。

### 2 Setup

```bash
npx rea-agents setup
```

要点：

- setup 先显示计划，用户批准后才写配置或安装 Hopper。
- npm 下载批准和 setup 批准是分开的。
- 常用参数：`--client`（可重复）、`--all-detected`、`--skill=false`、`--dry-run`。
- `--yes` 必须搭配显式范围，否则只作用于已有 REA 注册。
- 注册固定到执行 setup 的确切版本。

Claude Code 项目级注册示例：

```bash
claude mcp add --scope local rea -- npx -y rea-agents@6.8.0 mcp
```

不要用 `--scope project` 做本机临时注册。

> 依据：R3 `docs/installation.md:41-143`（setup 交互/批准、`--client`、`--all-detected`、`--skill=false`、`--dry-run`、`--yes`）；R3 `docs/installation.md:417-421`（update/uninstall）。

### 3 就绪检查

```bash
rea doctor --json
rea doctor --provider ghidra --json
rea doctor --client codex --json
rea doctor --skill --json
```

- `doctor` 是只读检查。
- `--provider` 检查 provider。
- `--client` 检查客户端适配器。
- `--skill` 检查技能。

> 依据：R3 `docs/installation.md:377-379`（doctor 检查一行 engine/client/skill）；R3 `docs/installation.md:417`（doctor 严格只读）。

### 4 依赖矩阵与安装顺序

把依赖分成“REA 必需”和“按能力启用”，新手最容易犯的错是一次性装一堆工具，结果环境互相冲突。

#### 4.1 必需

| 依赖 | 作用 | 检查 |
|---|---|---|
| Node 22.23.4+ / 24.22.1+ / 26.12.1+ | REA 运行时 | `node -v` |
| npm / npx | 安装/运行 `rea-agents` | `npm -v` |
| Linux 或 macOS | 本地分析/PTY | `uname -a` |
| `ps`（Linux procps） | 进程所有权/清理 | `ps --version` |
| 文件系统 + shell | 目标/Evidence/会话 | `pwd`、`ls` |

> 依据：R3 `docs/installation.md:1526`（Node）；R9 `docs/process-capture.md:9-31`（权限/PTY）；R3 `docs/installation.md:403`（Linux owned-process 需要 procps `ps`）；R3 `docs/installation.md:377-379`（doctor）。

#### 4.2 可选（按目标）

| 目标/能力 | 需要 |
|---|---|
| Go buildinfo、ELF notes、.NET 元数据、基础产物盘点 | 无额外 provider |
| 原生伪代码/调用图 | JDK + Ghidra，或 IDA，或 Hopper |
| Linux 调试 | GDB 或 Rizin |
| 快速反汇编/节区/符号 | GNU objdump |
| ELF 布局检查 | Python + pwntools/pyelftools/Unicorn，设置 `REA_PWNTOOLS_PYTHON` |
| Android APK/设备 | adb、JADX、apktool |
| pcap/协议 | TShark + capinfos |
| 浏览器/网页 | Chrome-family 浏览器 |
| WASM | WABT |
| 信号 | sigrok-cli |
| 网络抓包 | mitmproxy |

> 依据：R3 `docs/installation.md:637-650,965-1000`；R4 `docs/ida-provider.md:1-80`；R10 `docs/binary-diagnostics.md:15-31`；R11 `docs/reverse-engineering-tools.md:3,37-80`；R13 `docs/testing.md:2014`。

#### 4.3 建议安装顺序

1. Node/npm。
2. `npx rea-agents setup`（先只注册 CLI/MCP，不装 provider）。
3. 跑 `rea doctor --json`，确认基础环境。
4. 需要原生分析时再装 JDK + Ghidra；配置 `JAVA_HOME`、`GHIDRA_INSTALL_DIR`，跑 `rea doctor --provider ghidra --json`。
5. 有 IDA 安装/许可和对应 IDA MCP 注册时再配置；IDA MCP 桥可以开源，但没有 IDA 引擎许可不够；Hopper 同理。没有许可不要硬装破解版。
6. 需要 Python 布局工具时，单独建虚拟环境安装 pwntools/pyelftools/Unicorn，并用绝对路径设置 `REA_PWNTOOLS_PYTHON`。
7. 需要浏览器/pcap/Android/WASM 时再装对应工具。

`npx rea-agents setup` **不会**安装/升级 Java、Ghidra、IDA、Hopper、Node、Homebrew 等；provider 是你的责任。

> 依据：R3 `docs/installation.md:417-425`（update/uninstall 只处理 REA 拥有的注册/技能；保留 Hopper、Node 等）；R3 `docs/installation.md:637-650`。

#### 4.4 平台注意

- Linux 上进程相关能力依赖 procps 的 `ps`。
- 新进程捕获需要原生 PTY；Windows 只能比较已有 capture Evidence。
- 某些 provider 只支持特定平台/架构（例如 Hopper Linux 仅 x86_64）。
- 版本/能力在实测前可能 unknown；用 `rea capabilities --json` 看当前安装。

> 依据：R3 `docs/installation.md:403`（procps）；R3 `docs/installation.md:637-650`（Hopper 平台）；R9 `docs/process-capture.md:9-31`（PTY/Windows）；W6 `entity-rea-installation.md`。

### 5 Ghidra/IDA/Hopper 怎么选

先看决策树：

```text
只需要 Go 构建信息 / ELF notes / .NET 元数据 / 基础盘点？
  └─ 用内置读取器，不需要 Ghidra/IDA/Hopper

需要原生函数的伪代码/调用图/类型？
  ├─ 没有商业许可，想免费/自动化 → Ghidra
  ├─ 已有 IDA Pro/Home + Hex-Rays，目标复杂 → IDA
  ├─ 已有 Hopper，主要 macOS/Linux x86_64 → Hopper
  └─ Android/DEX 为主 → JEB

需要运行时调试？
  ├─ Linux → GDB / Rizin
  └─ 浏览器/设备 → 浏览器场景 / adb

需要快速看反汇编/节区？
  └─ objdump
```

| 维度 | Ghidra | IDA | Hopper |
|---|---|---|---|
| 许可 | Apache 2.0，免费 | IDA Pro/Home 商业；IDA Free 免费受限；IDA MCP 开源（MIT） | 商业 |
| 平台 | Java 跨平台 | Windows/macOS/Linux | macOS / Linux x86_64 |
| 自动化/headless | 强 | 需要配置 | 一般 |
| 交互体验 | 一般 | 强 | 强（macOS） |
| REA 启动超时 | 330000 ms | 按 provider | 120000 ms |
| 适合 | 免费、批量、CI、学习 | 复杂二进制、已有许可 | macOS/快速交互、已有许可 |

> 官方 IDA MCP（Code Mode，`HexRaysSA/ida-mcp`）是 MIT 开源的桥接层，要求 IDA 9.4+ with idalib；REA 文档当前验证的是 `mrexodia/ida-pro-mcp`（IDA Pro）与可选的 `ida-free-mcp`（IDA Free），官方 Code Mode 能否直接作为 REA 上游取决于工具 profile 是否匹配。

> **IDA Free 不适配自动化**：免费版架构/加载器/插件/自动化能力少于 Pro/Home，反编译依赖云反编译（联网、可能要求同意、上游遍历限制）；REA 只能走 GUI-attached 的 `ida-free-mcp`，没有 native headless，direct callers 不可用，插件默认绑 `0.0.0.0`。IDA Free 适合学习/轻量查看，不建议作为 REA 的自动化主路线；优先 IDA Pro/Home 或 Ghidra。

**本教程的建议**：

1. 先用内置读取器完成第 3–4 章；这一步不需要 Ghidra/IDA。
2. 真正需要函数级伪代码时，再装 Ghidra（免费、可自动化）。
3. 如果你已经有 IDA 安装/许可（以及对应的 IDA MCP 注册）或 Hopper 许可，可以按 2.6 配置；IDA MCP 开源不等于 IDA 引擎许可，没有许可不要使用破解版本。
4. 不要在 279 MB 的 WeKnora Lite 上做第一次 Ghidra 实验；先用小二进制熟悉流程。

> 依据：R3 `docs/installation.md:637-650,965-1000`；R4 `docs/ida-provider.md:1-80`；R5 `docs/ghidra-provider.md:1-40`；W2 `concept-rea-provider-architecture.md`。

### 6 Provider 前置

| Provider | 前置 |
|---|---|
| Hopper | macOS 12+ / Linux x86_64；启动超时默认 120000 ms |
| Ghidra | 12.1.x + 64 位 JDK + 宿主原生 decompiler；`GHIDRA_INSTALL_DIR`、`JAVA_HOME`；启动超时默认 330000 ms |
| IDA | IDA Pro/Home 或 IDA Free + 对应 IDA MCP 注册（`REA_IDA_MCP_CONFIG`）；REA 只读，不安装/授权 |
| 静态 JS/.NET | 不需要原生引擎；JS 静态分析只需 Node/npm |
| objdump/GDB/Rizin/Cutter | 由用户提供；各自有版本和平台限制 |
| Python/pwntools | `REA_PWNTOOLS_PYTHON` 指向绝对路径；pwntools 4.15.0 + pyelftools 0.33 + Unicorn 2.1.2 |

> 依据：R3 `docs/installation.md:637-650,965-1000,377-379`；R4 `docs/ida-provider.md:1-80`；R10 `docs/binary-diagnostics.md:15-31`；R13 `docs/testing.md:2014`；E1 本机实测。

### 7 更新与卸载

```bash
rea update
rea uninstall
rea uninstall --purge-data
```

- `update` 只更新拥有当前 CLI 的全局安装。
- `uninstall` 只删 REA 拥有的注册/技能。
- `--purge-data` 另外清理缓存。

> 依据：R3 `docs/installation.md:417-425`。

### 8 本章练习

1. 跑 `rea doctor --json`，记录缺失的 provider。
2. 跑 `rea capabilities --json`，找出一个 `effects` 非空的操作，并说明它的副作用。
3. 判断下面任务分别需要什么依赖：
   - 读取 Go buildinfo
   - 生成原生函数伪代码
   - 捕获 CLI 终端输出
   - 检查 pcap
   - 观察浏览器页面
4. 如果你的 agent 客户端支持 MCP，尝试注册 REA，然后用 `rea mcp doctor --json` 检查。

### 9 常见问题

| 现象 | 原因/处理 |
|---|---|
| Setup 报 Node 不支持 | 检查是否 23/25，或版本低于最低要求 |
| 注册成功但工具不可见 | 注册 ≠ 工具到达模型；检查客户端启动器、PATH、超时 |
| Ghidra 不可用 | 检查 JDK、`GHIDRA_INSTALL_DIR`、native decompiler |
| IDA/Hopper 不可用 | 检查 IDA 安装、IDA MCP 注册（`REA_IDA_MCP_CONFIG`）、许可证/版本；IDA Free 使用 `ida-free-mcp`；Hopper 检查平台/安装/许可 |
| IDA Free 能用吗 | 可以用于学习/轻量查看；但云反编译需联网/同意，REA 只能 GUI-attached，无 native headless，direct callers 不可用，不建议自动化 |
| Hopper 不可用 | 检查平台、安装路径、启动超时 |
| 进程捕获失败 | 检查原生 PTY、procps 的 `ps`、平台支持 |
| `inspect-binary-layout` 报 `provider_unavailable` | 没装 pwntools/pyelftools/Unicorn，或 `REA_PWNTOOLS_PYTHON` 不是绝对路径 |
| 浏览器捕获失败 | 没有 Chrome-family 浏览器/Playwright 依赖 |
| pcap 检查失败 | 没有 tshark/capinfos |
| WASM 检查失败 | 没有 WABT |
| 不要用破解版 IDA/Hopper | 许可是用户责任；REA 不提供激活/许可证 |
